# bulk-reader — 大きなファイルは自分で読まず、要約を受け取る

エージェントの仕事の大半は考えることではなく読み書きです。大きなファイルを頭から
読むと文脈を大量に消費するので、**読む作業だけを安いワーカーモデルに委譲**します。

## 使い方

```bash
{{BULK}} <ファイルパス> "<知りたいことを具体的に>"
```

質問は具体的にするほど良い要約が返ります。悪い例「このファイルを説明して」／
良い例「字幕PNGを作る関数の名前と、折り返しの規則を教えて」。

## いつ使うか

- Read が「直接読むと文脈を大量に消費します」とブロックされたとき
- 350行を超えるファイルの中身を知りたいとき
- 複数の大きなファイルをまたいで調べたいとき（1ファイルずつ呼ぶ）

## 使ってはいけないとき

- **ファイルを編集するとき**。要約には信頼できる行番号が入らないので、
  編集対象は部分読み（Read の offset/limit）で正確に見ること
- 350行以下の小さいファイル。委譲の手間のほうが高くつく
