# 読み込みを横取りする仕組み（と、それが効かなかった話）

動画の要点：「AIが大きなファイルを読むのを止めて、安いAIに要約させれば使用量が9割減る」という
方法を、そのまま自分の環境に入れて18回ぶん測った。結果は——**見張りは延べ120回働いて、実際に
止めたのは2回だけ。安いAIの出番はゼロ**。トークンも減らなかった。

理由は単純で、**AIはもともと大きなファイルを丸ごと読んでいなかった**。先に検索で当たりを
つけて、必要な範囲だけ読む。止める相手がいなければ、どんなに良い仕組みも働かない。

そして本当に量を食っていたのは読み込みではなかった。入力の **92%** は「前のやりとりの送り直し」で、
読み込みは **8%** しかない。8%をまるごとゼロにしても、減るのは8%までになる。

このサンプルには、**同じ仕組み**と、**自分の環境で効くかどうかを先に測る道具**が入っている。

## まず、自分の環境を測る（お金もAPIキーも要らない）

```
python3 check_my_sessions.py
```

Claude Code が自動で残している作業の記録（`~/.claude/projects/`）を読んで、
**自分のAIが本当に大きなファイルを丸ごと読んでいるか**を数える。
**AIは1回も呼ばない**ので無料で、中身をどこかに送ることもしない。

出力の最後に、こう出る:

```
判定: 大きく読んでいるのは主にコード以外（画像・PDFなど）でした。
      → これらは要約モデルに回せないことが多く、横取りの効き目は限られます。
補足: 入力の 98% は「前のやりとりの送り直し」です。
      読み込みを削るより、会話を短く区切るほうが効きます。
```

**まずこれを見てから、下の仕組みを入れるか決めてほしい。** 動画で言いたかったのはここ。

## 仕組みそのもの

| ファイル | 中身 |
|---|---|
| `shunt.py` | 見張り本体（Claude Code の PreToolUse hook）。350行を超えるファイルの読み込みと、`cat`/`head`/`tail`/`less`/`more` での読み出しを止め、要約担当への案内を返す |
| `bulk-reader` | 要約担当。安いモデル（haiku）にファイルを読ませ、要約だけを返す |
| `skills/bulk-reader/SKILL.md` | 「大きいファイルは自分で読まず、要約を受け取る」ことを Claude に伝えるスキル |

### 入れ方

1. `shunt.py` と `bulk-reader` を好きな場所に置く（`bulk-reader` は `chmod +x`）
2. `skills/bulk-reader/SKILL.md` をプロジェクトの `.claude/skills/bulk-reader/SKILL.md` へコピーし、
   本文中の `{{BULK}}` を `bulk-reader` の**絶対パス**に置き換える
3. プロジェクトの `.claude/settings.json` に見張りを登録する:

```json
{
  "hooks": {
    "PreToolUse": [
      { "matcher": "Read|Bash",
        "hooks": [{ "type": "command", "command": "python3 /絶対パス/shunt.py" }] }
    ]
  }
}
```

環境変数 `SHUNT_MIN_LINES`（既定 350）で閾値を、`SHUNT_BIN` で要約担当のパスを変えられる。

### つまずきやすいところ（実際に踏んだ）

- **`bulk-reader` を PATH で通すと `command not found` になる。** Claude の Bash は
  ユーザーのシェル設定を読み込むので、渡した PATH が上書きされる。**絶対パスで書くこと**
- **hook だけ置いてもスキルを登録しないと、要約担当は使われない。** AI は止められても
  `grep` や部分読みで自力で回り込む
- **止めていない読み方が1つでもあれば、そこから抜ける。** `cat` を塞いだら次の1手で
  `sed -n '1,60p'` に切り替えられた。全部塞ぐと今度は仕事ができなくなる

## 実測の結果

`results/` に生データがある（`sandbox` / `session` / `ts` は個人情報を含むため除去済み）。

**1本のファイルで「止まった／代わりに読ませた」を実演した記録は [`evidence/`](evidence/)**
（5,507行のファイルが止められた記録と、安いAIが47秒で要約した記録。それぞれ1件ずつ）。

条件A＝素のまま／条件B＝見張りあり。3種類の作業を各3回ずつ、計18回（モデルは Opus 5）。

| 作業 | 素のまま | 見張りあり | 差 |
|---|---|---|---|
| 調べもの | 1,554,429 | 1,286,605 | −17.2% |
| バグ探し | 730,155 | 1,138,805 | **+56.0%** |
| 機能追加＋テスト | 1,168,446 | 1,176,200 | +0.7% |

（単位はすべて入力トークン。3回の平均）

**成果物の質は両条件で同じ**だった。バグ探しでは、仕込んでおいた不具合（音声キャッシュのキーから
話者IDが落ちていて、別の人の声が使い回される）を**6回とも両条件が発見**した。機能追加でも
6回とも実装とテストが入り、既存のテストは壊れていない。

### おまけ: 効いたのはモデル選びだった

同じ質問・同じ採点（挙げてほしい関数名9個のカバー率）で、モデルだけ変えた結果:

| | 入力トークン | 往復 | 関数名 |
|---|---|---|---|
| Opus 5 | 1,554,429 | 16.3 | 9/9 |
| Sonnet 5 | 307,054 | 3.7 | 9/9 |

約5分の1。Sonnet は指示していないのにサブエージェントを1体呼んで調べさせていた
（＝「読み書きは安いモデルへ」を、ファイル単位ではなく作業単位で最初からやっている）。
これは「Sonnet が優秀」ではなく「**この作業に Opus は過剰だった**」という話。

## Claude Code にどう頼むか

```
check_my_sessions.py を走らせて、私の環境で読み込みの横取りが効きそうか判断して。
効かなそうなら、代わりに何を削ればいいかも教えて。
```

## 注意

- 数値はすべて**特定の1つの環境での実測**。設定や使い方が違えば結果も変わる
- 元記事（Spotify）の主張を否定するものではない。あちらは Java の大規模な社内リポジトリでの測定で、
  条件がまったく違う
- `check_my_sessions.py` の文字数からトークンへの換算は概算（3.2文字/トークン）
